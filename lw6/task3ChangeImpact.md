## 1 
PictureDocument. Должна измениться команда удаления фигур

CanvasController. Должен понимать работает ли он с группой или нет, исходя из этого менять свое поведение относительно выделения фигур.

EditorModel. Должен научиться создавать новую команду, искать фигуры внутри групп, разделять запросы найти группу по клику и найти фигуру в группе по клику

EditorShape. Сейчас представляет собой обёртку над IShape из Model. Это делает невозможным изменение одной конкретной фигуры, т.к. EditorShape имеет один общий PreviewOffset для всей IShape.

Views. Текущий вид класса EditorShape не позволяет реализовать новое требование. Возможные пересмотры устройства EditorShape или внедренние новых классов вероятно вызовет изменение всех View

## 2 
Пользователь нажимает ЛКМ по группе -> появляется событие передающееся от EditorWindow -> CanvasView -> CanvasController, CanvasController просит EditorModel выделить фигуру по координатам, группа выделяется.

Пользователь нажимает по вложенным фигурам выделенной группы, событие доходит до контроллера, контроллер просит отдельно выделить фигуру по координатам, EditorModel видит что точка принадлежит выделенной группе и ищет вложенную фигуру по этим координатам, если фигура оказалась группой, то ищет конкретную фигуру внутри неё, фигуры выделяются.

Пользователь нажимает кнопку Delete. событие доходит до контроллера, он просит EditorModel удалить выделенные фигуры. EditorModel создает нужную команду, она записывается в историю, выполняется, обновляется Model, обновляется EditorModel

## 3 

Может изменится связь между CanvasController и EditorShape, контроллер может быть вынужден больше знать о внутреннем устройстве EditorShape, уметь определять является ли она группой или нет.

Может измениться взаимодействие между View и EditorModel, т.к. в текущем виде EditorShape не может поддержать изменения.

## 4
Текущий подход с EditorShape в виде обертки для IShape не позволяет поддержать семанитку Preview/Commit для вложенных групп. Большая часть логики EditorModel построена на семантике обертки класса EditorShape над IShape, её пересмотр может вызвать серьезные изменения в EditorModel.

Классы EditorShape, IEditorShapeVisitor используются во Views, поэтому их пересмотр может вызвать большой пласт изменений во Views

В текущей реализации CanvasController занимается логикой выделения/снятия выделения с фигур, если были зажаты клавиши Ctrl или клик был по пустому месту. Сложная логика работы с выделением вложенных фигур может стереть границы между CanvasController/EditorModel, и вынудить внести эту логику в EditorModel, также раздувая класс не его ответственностью.

Логика разгруппировки должна жить в команде, т.к. должна поддерживать Undo/Redo, это либо вынудить создавать команду, выполняющую несколько действий (Удаление + разруппировка), либо, возможно, переход к макрокомандам. 

## 5

1. 
- as-is: Команда DeleteShapeCommand занимается только удалением 
- to-be: DeleteShapeCommand берет на себя логику разгруппировки

2. 
- as-is:  Клик по фигуре группы выделяет группу целиком 
- to-be:  Клик по вложенной фигуры выделенной группы выделяет эту фигуру

3.
- as-is: Нельзя удалить вложенные в группу фигуры
- to-be: Группа поддерживает удаление вложенных фигур и распадается, если их <2
